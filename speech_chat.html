    About Voice Console

    Voice Console is the browser client for the AI voice chat demo built on Axway Amplify Fusion. You talk or type to an AI assistant, and every message travels over a single WebSocket connection to a Fusion integration that handles transcription, the AI conversation and the spoken reply.

    Amplify-Fusion-AI-Voice-Chat-Demo-Using-MistralProject source, Fusion export and setup guide on GitHub

    How a voice turn works

    1. You hold the talk button and speak. The browser records your voice and sends it to Fusion as a 16 kHz WAV file.
    2. Fusion transcribes the audio with Mistral speech-to-text and sends back what it heard, which appears in your message bubble.
    3. Fusion passes the text to the AI chat model (Mistral, with Gemini as a fallback) and keeps the conversation history in Postgres, so the assistant remembers earlier turns.
    4. The reply comes back as text and as speech from Mistral text-to-speech, which plays automatically.

    Getting started

    1. Open and enter the WebSocket base URL, for example wss://host:4443/ws. The app adds /speech for you.
    2. Add the API key from your consumer app in Amplify Fusion Manager.
    3. Click Connect, then hold the talk button or the Space bar and speak.

    Ways to send a message

    Talk
    Push to talk. Hold to record, release to send. Pressing it while a reply is playing interrupts the reply.
    Type
    Send a text message. Press Enter to send and Shift+Enter for a new line.
    Audio file
    Send a recording you already have, such as a WAV or MP3. Drag it in or choose a file.
    Record
    Record, listen back, then decide whether to send or discard it.

    Trace

    The Trace tab keeps a history of every exchange on the connection: what you sent and each response the server returned, with sizes and timings. Audio is summarized rather than shown in full. Use Copy as JSON to share a session when debugging.

    Message format

    The app connects to <base>/speech?conversationId=<id>&x-api-key=<key>. The key goes in the address because browsers can't add headers to a WebSocket.

    DirectionFrameContent
    SentText{"type":"CHAT","message":"…"}
    SentBinaryVoice as 16 kHz mono WAV, or an audio file as-is
    ReceivedTextOne event or an array of events: RESPONSE, TRANSCRIBED_REQUEST or ERROR, each with a message. Plain text is shown as the reply.
    ReceivedBinarySpoken reply audio, played automatically after voice messages

    Troubleshooting

    Won't connect
    A close code of 1006 usually means the server rejected the connection. Check the base URL and API key in Settings, and that the Fusion WebSocket server is running.
    Microphone blocked
    Allow the microphone from the icon at the left of Chrome's address bar, and turn on Google Chrome in macOS System Settings → Privacy & Security → Microphone.
    No sound detected
    Pick a different input device in Settings and use Test to check the level.
    Reply doesn't play
    If the browser blocks auto-play, press play on the reply once and it will be allowed for the rest of the session.
